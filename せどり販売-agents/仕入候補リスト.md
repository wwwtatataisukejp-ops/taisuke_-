# 仕入候補リスト運用 — 社長は GO / NO GO のみ

> 作成: 2026/07/27 ／ 運用主体: 01市場リサーチ部・02仕入部
> 目的: **探索・調査・計算をチームが行い、社長の作業を「判断」だけに限定する**

---

## ⚠️ 最初に：このリストの相場欄が空である理由

```
相場（実際の成約価格）は、各販路の売却実績からしか取得できません。
本リストの「相場」「成約件数」「出品者数」は未取得です。

→ チームが実データで埋めるまで、GO/NO GO の判断はできません。
→ 埋まっていない候補を社長に上げてはいけません。
```

本リストが提供するのは**「どの型番を見に行くか」の探索対象**です。
数字の取得は、以下の手順でチームが行います。

---

## 1. 社長の役割（これだけ）

```
社長がやること   : 仕入提案書を見て「GO」または「NO GO」と言う
社長がやらないこと: 商品探し、相場調べ、計算、出品文作成、価格改定
```

### 社長に上げてよい提案書の条件（1つでも欠けたら上げない）
- [ ] 相場が**売却実績の中央値**で取得済み（出品価格ではない）
- [ ] 直近30日の成約件数が**4件以上**
- [ ] 出品者数を実数でカウント済み
- [ ] 上限仕入値（相場×0.57）を計算済み
- [ ] 実際の仕入可能価格が上限以下
- [ ] `law-checker` の判定が「問題なし」
- [ ] `cashflow-planner` の予算枠内
- [ ] 最悪シナリオ（相場20%下落・売れ残り）を計算済み

**条件を満たさない候補は、チーム内で握りつぶします。**
社長の時間を「判断できない案件」に使わせないことが、この仕組みの目的です。

## 3. 定例サイクル

### 毎日（チーム）
| 時間帯 | 担当 | やること |
|---|---|---|
| 随時 | `store-sourcer` `online-sourcer` | 候補の発見。90秒判定で足切り |
| 随時 | `roi-calculator` | 通過した候補の数値計算 |
| 随時 | `law-checker` `platform-policy-guard` | 法令・規約の確認 |
| 1日1回 | `cashflow-planner` | 予算枠の確認 |
| **1日1回** | 司令塔 | **条件を満たした候補だけを提案書にして社長へ** |

### 毎週（チーム）
| 担当 | やること |
|---|---|
| `demand-forecaster` `competitor-analyst` | ウォッチリストの相場・出品者数を更新 |
| `trend-scout` | 値上がり前兆の探知（生産終了・供給停止） |
| `niche-hunter` | ウォッチリストに追加する型番の発掘 |
| `inventory-manager` | 滞留リスト（30/60/90日超）の出力 |
| `automation-architect` | 上限仕入値 早見表の更新（スマホ閲覧用） |

### 毎月（チーム）
`kpi-analyst` 議長で P5 月次レビュー → 提案の的中率を検証し、
**「GOしたのに基準未達だった案件」の原因を分析**してウォッチリストを改訂

## 4. 相場の取得手順（チームが実行する）

`01-sourcing-playbook.md` 第2章に準拠。

```
① 型番で完全一致検索する（型番違い・世代違いを混ぜない）
② **売却済みの実績だけ**を抽出する（出品中の価格は相場ではない）
③ 直近30日に絞る
④ 同一コンディション帯に絞る
⑤ **中央値**を採る（平均値は外れ値に歪む）
⑥ サンプル数を記録する
⑦ 出品者数を数える（自分が入る前の状態）
⑧ 上限仕入値 = 中央値 × 0.57 を計算して記入
```

### サンプル数による扱い
| 直近30日の成約件数 | 扱い |
|---|---|
| 10件以上 | 信頼できる。提案可 |
| 4〜9件 | 提案可。ただし回転を保守的に |
| **3件以下** | **提案しない**（相場未確定） |
| 0件 | ウォッチリストから除外 |

## 6. この型番を選んだ理由（`niche-hunter` の判定）

| 条件 | 電動工具 | オーディオ |
|---|---|---|
| ①型番で相場が確認できる | ◎ 型番が明確 | ◎ 型番が明確 |
| ②状態で価格が動く | ◎ 付属品有無で倍近く動く | ◎ 消耗品状態が効く |
| ③真贋リスクが低い | ○ 模倣品はあるが判別容易 | ○ |
| ④出品者が少ない | ○ 型番によっては薄い | ○ |
| ⑤売り手が素人 | ◎ 店舗が型番差を把握していない | ○ 「古い＝安い」の誤認 |
| ⑥単価¥12,000〜25,000 | ◎ | ◎ |

### 特に情報差が大きいポイント（現場で狙う）
1. **バッテリー・充電器の有無がタイトル・値札に反映されていない**
   → 「本体のみ」が「セット」と同じ値札で並んでいることがある
2. **世代違い（TD172D と TD173D 等）が同じ値札**
   → 型番1文字の差で相場が数千円変わる
3. **オーディオの「古い＝安い」誤認**
   → 評価が固まった名機が、年式だけで安く値付けされる

## 7. 提案の質を検証する（毎月）

`kpi-analyst` が月次で以下を検証し、ウォッチリストを改訂します。

| 指標 | 意味 | 目標 |
|---|---|---|
| 提案件数 | チームが上げた提案書の数 | — |
| GO率 | 社長がGOした割合 | 70%以上 |
| **提案の的中率** | GOした案件のうち、実績がROI50%を満たした割合 | 80%以上 |
| 見送り理由の分類 | NO GOの理由（数字／リスク／資金） | — |

### GO率が低い＝チームの足切りが甘い
社長がNO GOを連発している場合、**社長の時間を無駄にしています**。
提案の条件（第1章）を厳しくしてください。

### 的中率が低い＝相場の取り方が間違っている
GOしたのに基準未達だった案件は、ほぼ**相場を出品価格で取っていた**か
**回転を楽観していた**のどちらかです。原因を特定して手順を直します。
