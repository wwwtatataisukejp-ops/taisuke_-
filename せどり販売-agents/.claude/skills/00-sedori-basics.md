# 00 せどり基礎 — 全エージェント常時参照

> このマニュアルは**全34エージェントが必ず読む**共通OSです。
> ここに書かれた用語・計算式・数値基準に反する出力は、司令塔が差し戻します。

---

## 1. 事業の定義

せどり販売は「**価値の見落としを買い、必要な人に適正価格で届ける**」事業です。
利益の源泉は3つしかありません。

| 利益の源泉 | 意味 | 例 |
|---|---|---|
| **情報差** | 売り手が相場を知らない | 店頭で相場の1/3の値札 |
| **場所差** | 売る場所を変えると価値が上がる | 地方の店頭 → 全国のAmazon |
| **手間差** | 手を加えると価値が戻る | 清掃・欠品補完・セット組み |

**この3つのどれにも当てはまらない仕入れは、単なる在庫の移動**です。
仕入判断の際は「どの源泉で儲けるのか」を必ず1つ言語化してください。

---

## 2. 3大制約（すべての判断の上位ルール）

1. **キャッシュ制約** — 資金は有限。回転しない在庫は「死んだ現金」。
   利益率が高くても回転しない商品は、利益率が低くても回転する商品に負けます。
2. **時間制約** — 社長の時間が最大のボトルネック。
   1時間かけて¥500稼ぐ提案は、原則として却下対象です。
3. **アカウント制約** — アカウント停止は事業の即死。
   **規約 > 短期利益**。判断に迷ったら、必ず利益ではなく安全を選びます。

## 3. 共通用語（全部門で表記統一）

| 用語 | 定義 | 補足 |
|---|---|---|
| 仕入値 | 商品本体の取得原価（税込） | 送料・手数料は含めない |
| 仕入原価 | 仕入値 ＋ 仕入時送料 ＋ 仕入時手数料 | 実際に出ていった金額 |
| 想定売価 | 実際に「売れている」価格 | ×出品価格 ○売却実績価格 |
| 販売手数料 | 販路に支払う成約時手数料 | → `02-pricing-and-roi.md` |
| 販売経費 | 販売手数料 ＋ 出荷送料 ＋ 梱包材費 | 広告費があれば加算 |
| **粗利** | 想定売価 −（仕入原価 ＋ 販売経費） | せどりで言う「利益」はこれ |
| **粗利率** | 粗利 ÷ 想定売価 | 売価に対する利益の厚み |
| **ROI** | 粗利 ÷ 仕入原価 | 資金効率。せどりで最重要 |
| 回転日数 | 仕入から入金までの日数 | 出品〜売却ではなく**入金まで** |
| 滞留在庫 | 仕入から90日を超えた在庫 | 在庫金額の10%以下に抑える |
| 在庫比率 | 在庫評価額 ÷ 総運転資金 | 70%が上限 |
| 死に在庫 | 想定売価 < 仕入原価 になった在庫 | 損切り対象 |
| 相場 | 直近30日の売却実績の中央値 | 平均値ではなく**中央値**を使う |
| モノレート的確認 | 売却実績の個数と価格帯の確認 | 販路の売却履歴から取得 |

### 「相場」に平均値を使わない理由
1個だけ極端に高く売れた記録が平均を引き上げ、判断を誤らせます。
**必ず中央値（真ん中の価格）**を採用し、サンプル数も併記してください。
例：`相場 ¥12,800（直近30日 実績11件の中央値／2026-07-27時点）`

## 4. 利益計算の基本式（詳細は `02-pricing-and-roi.md`）

```
粗利   = 想定売価 −（仕入原価 + 販売手数料 + 出荷送料 + 梱包材費）
粗利率 = 粗利 ÷ 想定売価 × 100
ROI    = 粗利 ÷ 仕入原価 × 100
月次資金回転率 = 30日 ÷ 回転日数
実質年利回り  = ROI × (365 ÷ 回転日数)
```

### なぜ ROI と回転日数を必ずセットで見るのか
- ROI 30%・回転30日 → 実質年利回り **365%**
- ROI 60%・回転180日 → 実質年利回り **122%**

**ROIが2倍でも、回転が6倍遅ければ負けます。**
利益額だけを見た提案は、司令塔が差し戻します。

## 5. 数値基準（合格ライン／CLAUDE.md 第8章と同一）

| 指標 | 合格ライン | 判定 |
|---|---|---|
| 粗利率 | 20%以上 | 下回れば原則 NO GO |
| ROI | 30%以上 | 下回れば原則 NO GO |
| 1商品あたり最低粗利 | ¥500以上（単価¥5,000未満）<br>¥1,500以上（単価¥5,000以上） | 作業工数の回収下限 |
| 想定回転日数 | 45日以内（上限60日） | 60日超は原則 NO GO |
| 在庫比率 | 総運転資金の70%以下 | 30%は現金でキープ |
| 滞留在庫（90日超） | 在庫金額の10%以下 | 超過時は P3 起動 |
| 返品率 | 3%以下 | 超過時は検品・説明文を見直し |
| 悪い評価率 | 1%以下 | 超過時は `cs-responder` が原因分析 |

### 合格ラインを割っても GO にできる例外（必ず理由を明記）
1. **回転が極端に速い**（7日以内）→ 粗利率15%まで許容
2. **継続仕入ルートの試験購入**（今後の再現性が価値）→ 初回のみ許容
3. **セット組み・欠品補完の前提**で、加工後に基準を満たす見込みがある

例外を使うときは、出力に `【基準例外】理由：◯◯` を明記してください。

## 6. 判定の3択（曖昧な結論を書かない）

すべての仕入・販売判断は、必ずこの3つのどれかで結論を出します。

| 判定 | 意味 | 使う条件 |
|---|---|---|
| **GO** | 実行してよい | 数値基準を満たし、法令・規約リスクなし |
| **保留** | 情報が足りない | 不足情報を**具体的に3つ以内**で提示すること |
| **NO GO** | 実行しない | 基準未達、または赤線（第7章）に抵触 |

「様子を見ましょう」「悪くないと思います」のような**判定を避けた表現は禁止**です。

## 7. 絶対NG（赤線・CLAUDE.md 6.4 と同一）

1. 真贋がグレーなブランド品を「たぶん本物」で出品する
2. 商標・キャラクター権利を侵害する商品の取扱い
3. 許可が必要な商品（医薬品・酒類・チケット等）を無許可で扱う
4. 複数アカウントの規約違反的運用
5. 状態不良を写真・文章から意図的に省く
6. 資金の90%以上を在庫に変える

**赤線に触れた瞬間、他の数字がどれだけ良くても NO GO です。**
判断の順序は必ず `① 赤線チェック → ② 数値チェック` の順にしてください。

## 8. 数字の扱い方（全エージェント厳守）

### 8.1 事実と推測を必ず分ける
| 種別 | 書き方 |
|---|---|
| 実績値 | `¥12,800（直近30日 実績11件の中央値／2026-07-27時点）` |
| 推定値 | `推定 ¥12,000前後（根拠：同型番の旧モデル実績から換算）` |
| 不明 | `不明（社長に確認が必要）` ← **推測で埋めない** |

### 8.2 出典と時点を必ず付ける
数字には `（何から／いつ時点か）` を必ず括弧書きします。
時点のない数字は、司令塔が差し戻します。

### 8.3 情報が足りないときの質問優先順位
仕入・価格の判断で数字が欠けている場合、**推測で埋めず**、
以下の優先順位で**最大3つまで**社長に質問します。

```
① 仕入値はいくらか
② 現在の相場（実際に売れている価格）はいくらか
③ 想定回転日数はどのくらいか
```

## 9. 出力の型（全エージェント共通）

社内文書は `【結論】` から始めます。詳細な報告フォーマットは CLAUDE.md 第9章に従ってください。

```
【結論】GO ／ 想定粗利 ¥3,200（ROI 40%・回転見込み30日）

【根拠】
・相場 ¥12,800（直近30日 実績11件の中央値／2026-07-27時点）
・仕入原価 ¥8,000（本体¥8,000・仕入送料¥0）
・販売経費 ¥1,600（手数料¥1,280 + 送料¥250 + 梱包¥70）

【リスク】
・売れ残り時の想定損失 ¥2,500（相場が¥9,500まで下落した場合）

【次のアクション】
1. 本日中に仕入 → 検品後、`condition-grader` にコンディション判定を依頼

【社長判断が必要な点】
・なし
```
