## 1. 在庫台帳（`inventory-manager` の中核）

### 1.1 必須項目
| 列 | 項目 | 例 | 用途 |
|---|---|---|---|
| A | 管理番号 | `20260727-001` | すべての紐付けキー |
| B | 仕入日 | `2026/07/27` | 滞留日数の起点 |
| C | 商品名・型番 | `SONY WH-1000XM4` | 特定 |
| D | コンディション | `B` | 価格設計 |
| E | 仕入先 | `◯◯リサイクル 東◯店` | 仕入先別の成績分析 |
| F | 仕入値 | `¥8,000` | 原価 |
| G | 仕入送料 | `¥0` | 原価 |
| H | 仕入原価 | `¥8,000` | F+G |
| I | 想定売価 | `¥12,800` | 判断時の相場 |
| J | 出品日 | `2026/07/28` | 出品までのリードタイム |
| K | 出品販路 | `メルカリ` | 販路別の成績分析 |
| L | 現在価格 | `¥12,800` | 値下げ履歴 |
| M | 保管場所 | `棚A-3` | ピッキング |
| N | 状態 | `出品中` | 在庫 / 出品中 / 売却済 / 返品 |
| O | 売却日 | | 回転日数の終点 |
| P | 売却価格 | | 実績 |
| Q | 販売経費 | | 手数料+送料+梱包 |
| R | 粗利 | | P−H−Q |
| S | 回転日数 | | 入金日 − 仕入日 |
| T | 検品写真フォルダ | `photos/20260727-001/` | トラブル時の証拠 |

### 1.2 台帳運用の3つの鉄則
1. **仕入れたその日に登録する**（後でまとめて、は必ず漏れる）
2. **管理番号を現物に貼る**（シール・付箋）。台帳と現物が結びつかない在庫は事故
3. **状態列を必ず更新する**。「出品中」のまま売却済みの在庫が、二重販売を生む

### 1.3 滞留の自動検知（毎週）
```
経過日数 = 本日 − 仕入日

30日超：注意（値下げ検討 → `repricing-operator`）
60日超：警告（販路変更を検討 → `platform-optimizer`）
90日超：滞留在庫（P3 起動：損切り判断）
```

`inventory-manager` は毎週、**30日超・60日超・90日超の3リスト**を出力します。

## 2. 保管の設計

### 2.1 保管場所のルール
| 原則 | 内容 |
|---|---|
| **住所を決める** | 棚に `A-1` `A-2` のように番地を振る |
| **回転で並べる** | 早く売れる物を手前・取りやすい高さに |
| **先入先出** | 同一商品は古い個体から出荷する |
| **1箱1商品を原則** | 混載は取り違えとすり替えクレームの原因 |
| **通路を確保** | 探す時間＝時間制約の消費 |

### 2.2 保管に注意が必要な商品
| 種類 | 注意点 |
|---|---|
| バッテリー内蔵品 | 高温を避ける。**膨張していないか定期確認** |
| 精密機器 | 湿気対策（乾燥剤） |
| 衣類・布製品 | 防虫・防湿。長期保管で匂いが移る |
| 紙製品・書籍 | 直射日光での日焼け |
| 食品・化粧品 | **期限管理を台帳に列追加**。期限切れは廃棄損 |
| 大型品 | 保管コストが利益を食う。回転を最優先 |

### 2.3 保管コストの可視化
```
1商品あたり月間保管コスト ≒ (家賃 or 倉庫費 + 光熱費) ÷ 保管可能点数
```
自宅保管でも**ゼロではありません**（スペースの機会費用）。
`kpi-analyst` は滞留在庫の損失計算に、この保管コストを必ず含めてください。

## 3. 梱包基準（`packing-shipper` 用）

### 3.1 梱包の目的
1. **商品を無事に届ける**（破損クレームの防止）
2. **サイズを最小にする**（送料 = 粗利）
3. **開封体験を損ねない**（評価に直結）

この3つは**しばしば衝突**します。優先順位は `1 > 3 > 2` です。
送料を¥100削って破損すれば、商品代金と評価を失います。

### 3.2 標準の梱包手順
```
① 商品を防水（OPP袋・ビニール）で包む
② 緩衝材で全面を包む（角と突起部を厚めに）
③ 箱に入れ、隙間を緩衝材で埋める（振って動かないこと）
④ 明細・納品書を同梱（販路の規定に従う）
⑤ テープでH貼り（底面は必ず十字またはH）
⑥ 送り状を貼付。**発送前に管理番号と商品を照合**
⑦ 梱包直前の状態を撮影（→ `03-product-inspection.md` 第6章）
```

### 3.3 カテゴリ別の梱包
| カテゴリ | 追加の注意 |
|---|---|
| 家電・精密機器 | 元箱があれば使用。なければ厚手の緩衝材で全面保護 |
| 液晶・ガラス面 | 面に段ボール板を当てる |
| バッテリー内蔵品 | 配送方法の制限を確認。航空搭載不可の便がある |
| 衣類 | 圧縮しすぎない。**防水は必須**（雨濡れクレームが多い） |
| 書籍 | 角折れ防止に厚紙。防水必須 |
| 割れ物 | 「われもの注意」を指定。**指定しても割れる前提で梱包** |
| 大型品 | 集荷・持込の可否と料金差を事前確認 |

### 3.4 やってはいけない梱包
- 使用済みの汚れた箱をそのまま使う（評価が下がる）
- 緩衝材なしで隙間を残す
- 過剰梱包でサイズを1段階上げる（送料の無駄）
- 他店のロゴが入った箱をそのまま使う
- 商品より大きい箱に商品を1点だけ入れる

## 4. 配送方法の選定

### 4.1 選定の判断軸（優先順）
```
① 追跡があるか        → 追跡なしは「届かない」トラブルで詰む
② 補償があるか        → 高額品は必須
③ サイズ・重量に適合  → 規定超過は返送・追加料金
④ 料金が最小か        → ①〜③を満たす中で最安
⑤ 速度               → 販路の発送期限に間に合うか
```

**④（安さ）を①②より優先してはいけません。**
追跡なしの配送で「届いていない」と言われた場合、こちらに反証手段がありません
（`fraud-risk-officer` 案件の典型）。

### 4.2 配送方法の記入表（**自分で実数を埋める**）
> 料金・規格は改定されます。必ず配送会社・販路の公式ページで確認してください。

| 配送方法 | サイズ上限 | 重量上限 | 料金 | 追跡 | 補償 | 用途 |
|---|---|---|---|---|---|---|
| | | | ¥ | ○/× | ¥ | |
| | | | ¥ | ○/× | ¥ | |
| | | | ¥ | ○/× | ¥ | |
| | | | ¥ | ○/× | ¥ | |
| | | | ¥ | ○/× | ¥ | |

**確認日：____／出典：____**

### 4.3 匿名配送
個人間取引の販路では、匿名配送に対応しているものがあります。
- メリット：住所開示のトラブル回避、送り状作成の手間削減
- 確認点：対応サイズ、料金、補償額、対応する販路の条件

### 4.4 送料は必ず「発送前に」確定する
サイズが読めないまま出品して、**送料が想定を超えて赤字**になる事故が頻発します。
`packing-shipper` は出品前に、**梱包後のサイズと重量を実測**して
`roi-calculator` に渡してください（→ `02-pricing-and-roi.md` 第3章）。

## 5. 発送のオペレーション

### 5.1 発送前チェック（1件ごと・省略禁止）
- [ ] 管理番号と注文内容が一致しているか
- [ ] 付属品がすべて入っているか（**説明文の「あり」リストと照合**）
- [ ] 動作品は最終確認をしたか
- [ ] 個人情報（前所有者のデータ・書類）が残っていないか
- [ ] 梱包直前の写真を撮ったか
- [ ] 宛名・品名が正しいか
- [ ] 台帳の状態列を「売却済」に更新したか

### 5.2 個人情報の消去（見落としが多い）
中古品には前所有者の情報が残ります。**発送前に必ず消去**してください。
| 商品 | 消すもの |
|---|---|
| スマホ・PC・タブレット | 初期化、アカウントのサインアウト、**アクティベーションロック解除** |
| カメラ | SDカード抜き取り、本体メモリの初期化 |
| ゲーム機 | 本体初期化、アカウント削除 |
| プリンタ・複合機 | 保存文書の消去 |
| 手帳・書籍 | 書き込み・挟まれた書類 |
| 衣類・バッグ | ポケットの中身 |

**アクティベーションロックが残った端末は「使えない商品」**であり、
返品・低評価・詐欺申告の原因になります。検品時に必ず確認してください。

### 5.3 発送期限
販路が定める発送期限（例：◯日以内）を必ず守ります。
遅延は評価の低下とアカウント指標の悪化に直結します。
**期限に間に合わない場合は、発送前に必ず購入者へ連絡**（→ `cs-responder`）。

## 6. FBA・外部倉庫の運用（`fba-operator` 用）

### 6.1 FBA を使うかの判断
| FBAが向く | 自己発送が向く |
|---|---|
| 回転が速い定番商品 | 単発・一点物 |
| 複数個の同一商品 | 大型・重量物（保管料が高い） |
| 出荷作業の時間を削りたい | 低単価で手数料負けする商品 |
| 販路の優遇を受けたい | 長期保管になりそうな商品 |

```
FBA判定 = 自己発送の粗利 vs (FBAの粗利 + 削減できた作業時間 × 目標時給)
```

### 6.2 納品前チェック
- [ ] 出品制限・要申請ブランドに該当しないか（→ `05-platform-rules.md`）
- [ ] 危険物・要期限管理品の受入条件を満たすか
- [ ] ラベルの規格・貼付位置は正しいか
- [ ] 商品ラベルが**バーコードを隠していない**か
- [ ] 中古品のコンディション設定が自社ランクと整合しているか
- [ ] 納品プランの数量と実物が一致しているか
- [ ] 梱包が倉庫の受入基準を満たすか

### 6.3 納品後に必ず確認すること
- [ ] 受領数量が納品数と一致しているか（**差異は期限内に調査依頼**）
- [ ] 破損・紛失が発生していないか
- [ ] 長期保管手数料の発生時期を台帳に記録したか

### 6.4 長期保管の管理
FBA は保管期間が延びると**追加の保管手数料**が発生します。
`inventory-manager` は FBA 在庫についても90日ルールを適用し、
手数料発生前に `repricing-operator` へ回してください。

## 7. 返品・トラブル対応（`returns-handler` 用）

### 7.1 対応の順序
```
① 事実確認（謝罪より先）
   ・何が、いつ、どういう状態で届いたか
   ・写真を依頼する（外箱・梱包状態・商品）
② 自社記録との照合
   ・検品写真、梱包直前の写真、説明文の記載
③ 責任の所在を判定
   ・自社起因 / 配送起因 / 購入者起因 / 悪意
④ 対応方針の決定
⑤ 返信（→ `cs-responder` が文面作成）
⑥ 再発防止（検品・説明文・梱包のどこを直すか）
```

### 7.2 責任別の対応
| 起因 | 典型例 | 対応 |
|---|---|---|
| **自社** | 記載漏れ、検品ミス、誤発送 | 速やかに返品・返金。非を認めて謝罪 |
| **配送** | 輸送中の破損 | 配送会社へ補償申請。**梱包写真が必須** |
| **購入者** | 使用後の返品、イメージ違い | 販路の規約に従う。規約上応じる義務があるなら応じる |
| **悪意** | すり替え、虚偽の未着申告 | `fraud-risk-officer` へ即エスカレーション |

### 7.3 損失を最小化する原則
1. **争わない方が安いケースが多い**。返金額 < 対応時間 + 評価リスク なら即返金
2. ただし**悪意が疑われる場合は記録を残して争う**（前例を作らないため）
3. 返品された商品は**再検品**し、状態を更新して再出品するか判断する
4. 返品コストは `bookkeeper` に連携し、経費計上する

### 7.4 返品率が3%を超えたら
`00-sedori-basics.md` の基準を超過した場合、**個別対応ではなく構造の問題**です。
```
`kpi-analyst` が返品理由を分類
  → 「状態記載不足」が多い → `03-product-inspection.md` と `04-listing-copywriting.md` を見直す
  → 「破損」が多い         → 梱包基準を見直す
  → 「イメージ違い」が多い → 写真の枚数・角度を見直す
```

## 8. 週次・月次のオペレーション

### 毎週（`inventory-manager` 主導）
- [ ] 滞留リスト（30/60/90日超）を出力
- [ ] 台帳と現物の抜き取り照合（10点程度）
- [ ] 出品中なのに在庫がない／在庫があるのに未出品の商品を検出
- [ ] バッテリー品の膨張チェック

### 毎月
- [ ] 全在庫の棚卸（台帳と現物の完全照合）
- [ ] 在庫評価額の算出 → `bookkeeper` `tax-advisor` へ連携
- [ ] 在庫比率の確認（70%以下か）→ `cashflow-planner` へ連携
- [ ] 滞留在庫比率の確認（10%以下か）
- [ ] 梱包資材の在庫確認・発注
