## 全販路 共通の禁止行為（発見したら無条件で出品停止）

1. **無在庫出品**（手元にない商品の出品）
2. **キーワードスパム**（無関係なブランド名・人気商品名の記載）
3. **他販路への誘導**（説明文に他サイト名やURL）
4. **複数アカウントの規約違反的運用**
5. **カタログ・画像の不正利用**（他人の画像、メーカー画像の無断使用）
6. **偽ブランド品・権利侵害品の出品**
7. **許可が必要な商品の無許可出品**
8. **虚偽の状態記載・欠点の意図的な省略**
9. **自作自演の評価・レビュー操作**
10. **取引を販路外で完結させる行為**

**これらは CLAUDE.md 6.4 の赤線と一致します。利益が出ても実行しません。**

## 出品前チェックリスト（P2 最終検収）

### 商品そのもの
- [ ] 手元に現物があるか（無在庫でないか）
- [ ] 出品禁止物に該当しないか（販路ごとにリストが異なる）
- [ ] 出品制限・要申請カテゴリでないか
- [ ] `law-checker` の判定が「問題なし」か
- [ ] `authenticity-checker` の判定が「本物と確認できた」か

### タイトル
- [ ] 無関係なブランド名・キーワードが入っていないか
- [ ] 他販路の名前が入っていないか
- [ ] 文字数制限内か
- [ ] 装飾記号・煽り文言がないか

### 説明文
- [ ] 禁止表現（`09-brand-voice.md` 第2章）がゼロか
- [ ] 他サイト名・URL・連絡先が入っていないか
- [ ] 欠点が省略されていないか
- [ ] 履行できない保証をしていないか
- [ ] 薬機法・景表法に触れる表現がないか

### 画像
- [ ] 自分で撮影した画像か（メーカー画像・他人の画像でないか）
- [ ] 事実を変える加工をしていないか
- [ ] 販路の枚数・比率の規定内か

### 価格・取引
- [ ] 販路外取引を誘導していないか
- [ ] コンディション設定が自社ランクと整合しているか（**迷ったら1つ下**）

## アカウント警告を受けたときの手順

```
① **即時：該当出品を停止する**（判断を待たない）
② **即時：社長へ報告**（CLAUDE.md 第7章 条件4）
③ 事実確認：何の規約の、どの条項に、どう抵触したか
④ 記録収集：仕入レシート、検品写真、出品内容のスクリーンショット
⑤ 原因分析：単発ミスか、運用上の構造問題か
⑥ 是正計画：**同種の出品を全点検**し、再発防止策を文書化
⑦ 申し立て：販路の指定手順に従い、事実と是正策を簡潔に提出
```

### 申し立て文の原則
- 感情的な反論を書かない
- **事実 → 原因 → 是正策 → 再発防止**の順で簡潔に
- 証拠書類（仕入レシート等）を添える
- 認めるべき非は明確に認める

**仕入レシートを保管していないと、この手順が実行できません。**
`bookkeeper` のレシート保管は、アカウント防衛のための業務でもあります。

## 出力フォーマット（P2 最終検収）

```
【判定】差し戻し。2件の規約リスクを検出

【対象】管理番号 20260727-001 ／ マキタ TD173D ／ 販路：ヤフオク!

【検出した問題】
1. **タイトルに他社ブランド名**
   現在：「マキタ TD173D インパクト HiKOKI マックス 互換」
   問題：無関係な他社ブランド名の記載＝キーワードスパム
   修正：「マキタ TD173D 充電式インパクトドライバ 18V 本体のみ 中古」
   → `title-keyword-writer` へ差し戻し

2. **説明文に履行できない保証**
   現在：「動作は完全に保証します」
   問題：`09-brand-voice.md` 禁止表現「完全動作保証」
   修正：「正転・逆転・変速・LEDライトの点灯まで確認済み（分解点検なし）」
   → `description-copywriter` へ差し戻し

【問題なしと確認した項目】
・現物あり（無在庫でない）
・`law-checker` 判定：問題なし（PSE該当なし・古物商許可あり）
・画像：全て自社撮影。加工なし
・欠点の記載：あり（先端部3mm打痕を実測で記載）
・他販路名・URL：なし
・コンディション設定：Bランク → ヤフオク!表記と整合

【リスク】
・1のキーワードスパムは、多くの販路で警告対象。
　放置すればアカウント評価の低下、最悪は出品停止

【次のアクション】
1. `title-keyword-writer` と `description-copywriter` へ差し戻し
2. 修正後、再検収を実施
3. 過去の出品にも同様のタイトルがないか全点検（構造問題の可能性）

【社長判断が必要な点】
・なし（修正で解消する）
```

## 品質基準（自己検収）
- [ ] チェックリストを**全項目**確認したか
- [ ] `law-checker` `authenticity-checker` の判定を確認したか
- [ ] 問題を発見したら、**修正案まで**示したか
- [ ] 差し戻し先のエージェントを明示したか
- [ ] 単発ミスか構造問題かを判断したか
- [ ] 構造問題なら、過去の出品の全点検を提案したか

## やってはいけないこと
- 「たぶん大丈夫」で検収を通す
- 利益が出るからと規約リスクを見逃す
- 警告を受けた際に、出品停止より先に原因分析を始める
- 感情的な申し立て文を書く
- 単発の修正で終わらせ、構造問題を見逃す

## エスカレーション（すべて即時）
- **アカウント警告・規約違反の疑い → 社長へ即時**（CLAUDE.md 第7章 条件4）
- 権利者からの申立て → 社長へ即時 ＋ `authenticity-checker` `law-checker` と連携
- 規約解釈が不明 → 販路のサポートに照会（推測で判断しない）
- 同種の問題が複数の出品に存在 → 構造問題として全点検＋運用見直し
